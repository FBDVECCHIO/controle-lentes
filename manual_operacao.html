Arquitetura em Nuvem PWA + Supabase SQL

1. Arquitetura do Sistema e Como Funciona

O sistema foi migrado de uma estrutura local baseada apenas no Google Planilhas para uma arquitetura híbrida em nuvem. Isso divide a aplicação em três camadas independentes e integradas:

Fluxo de Comunicação de Dados
1. Celular / Computador
(PWA na Vercel)
➔
2. Servidor API
(Apps Script / doPost)
➔
3. Banco de Dados
(Supabase SQL)
  • Frontend (O Aplicativo): Hospedado de forma estática na Vercel. Garante carregamento instantâneo, responsividade de tela perfeita e permite que o sistema funcione como um aplicativo instalado (PWA) no celular de qualquer funcionário, sem passar pela App Store ou Google Play.
  • Backend (A API): O Google Apps Script (do seu painel do Sheets) serve como nosso backend. Ele possui a função doPost(e) que escuta as ações do aplicativo na Vercel e as executa com segurança.
  • Banco de Dados (Supabase PostgreSQL): O banco relacional na nuvem. Oferece alta performance, segurança, integridade dos dados e permite conexão direta via DBeaver no seu computador.

2. Checklist Passo a Passo para Implantação Final

  1. No DBeaver (Banco de Dados):
    • Conecte ao banco do Supabase.
    • Crie as tabelas vazias copiando e colando o script SQL fornecido na Fase 3 do Guia. Use o atalho Alt + X ou o Play com papel laranja para rodar tudo sem erros.
  2. No Apps Script (Backend):
    • Copie o código completo do arquivo local Code.gs.
    • No Google Sheets, abra Extensões > Apps Script, apague o código antigo e cole o novo por cima. Salve.
    • Clique em Implantar > Nova Implantação. Defina como Aplicativo Web, executar como "Eu", e acesso para "Qualquer um".
    • Implante, conceda permissões do Google e copie a URL do Aplicativo Web gerada.
  3. No arquivo index.html (Local):
    • Abra o arquivo index.html local e cole a URL do script na linha 8:
      var BACKEND_URL = "SUA_URL_DO_APPS_SCRIPT_AQUI/exec";
    • Salve o arquivo.
  4. No Terminal do Computador (Publicação):
    • Com o terminal aberto na pasta do seu projeto, publique a versão final em produção rodando:
      npx vercel --prod

3. Como Realizar Atualizações Futuras no Sistema

Sempre que você ou um desenvolvedor quiser fazer alterações no sistema no futuro, proceda de acordo com o manual abaixo para manter a segurança do ambiente:

Cenário 1: Alterações de Tela ou Visual (Apenas Frontend)

Exemplos: Mudar uma cor, alterar um texto ou aviso na tela, arrumar o layout de um botão.

  • Faça a alteração desejada diretamente no arquivo local index.html do seu computador.
  • Abra o terminal do seu computador na pasta do projeto e envie a atualização para a Vercel executando:
    npx vercel --prod
  • Resultado: O aplicativo é atualizado em tempo real para todos os usuários que usam no celular ou computador, sem necessidade de alterar nada no Google Sheets ou Supabase.

Cenário 2: Alterações de Lógica ou Regras de Negócio (Backend)

Exemplos: Alterar regras de login, mudar o cálculo de faturamento de relatórios, criar novos tipos de cadastros.

  • Modifique o arquivo local Code.gs no seu computador.
  • Copie o código completo do Code.gs e substitua o código dentro do Apps Script do Google Sheets. Salve.
  • Para colocar a alteração no ar, vá em Implantar > Gerenciar Implantações, clique no ícone de Lápis (Editar), selecione Nova Versão na caixa de seleção e clique em Implantar.
  • Resultado: O seu aplicativo da Vercel passa a usar a nova versão da API instantaneamente, sem precisar mudar a URL no código ou republicar o frontend.

Cenário 3: Alterações no Banco de Dados (SQL)

Exemplos: Adicionar um novo campo de texto nos formulários para salvar no banco (ex: "Observações"), criar novas tabelas de apoio.

  • Abra o DBeaver e adicione a nova coluna ou tabela de forma visual (ou executando um script SQL).
  • Atualize a lógica de gravação e consulta correspondente no arquivo Code.gs para ler e salvar esse novo campo.
  • Atualize a implantação no Apps Script para gerar uma nova versão da API (conforme o Cenário 2).
